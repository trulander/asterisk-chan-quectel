# Шаг 6: web-история звонков

## Контракт

Добавлены только per-SIM `GET /calls/<sim>` (HTML) и `GET /calls/<sim>.json?page=N` (JSON); общего `/calls` index нет. SIM валидируется существующим parser/existence-check. Параметр `page` использует существующий parser; страницы нумеруются с 1, значения вне границ clamp-ятся к `[1, pages]`. При нулевом total отображается пустая страница 1/1. Лимит SQL — строго 30 строк; последняя страница содержит остаток.

JSON envelope: `{ "device": "sim1", "page": 1, "page_size": 30, "total": 1, "pages": 1, "items": [...] }`. Item: `id` (`call-<rowid>`), `device`, `number`, `started_at` (сохранённое UTC), `direction` (incoming/outgoing/missed), `answered`, `finished`, `ended_at` (строка либо JSON null). HTML колонки: durable ID, номер, начало UTC, направление/тип, answered, finished, окончание UTC и Duration. Duration не добавляется в SELECT-ответ JSON или БД: HTML renderer вычисляет её из точных сохранённых `started_at`/`ended_at` в формате `YYYY-MM-DD HH:MM:SS UTC`. Положительный интервал показывается как `Dд HH:MM:SS`, нулевой — `0д 00:00:00`; отсутствующий конец, некорректная календарная дата, переполнение времени, обратный интервал или нехватка буфера дают `—`. Время не нормализуется молча: парсер требует ровно 23 символа, точные разделители и ASCII-цифры в каждой фиксированной числовой позиции, затем сохраняет календарную проверку и UTC round-trip. `call_paging_html_duration_fragment()` — небольшая функция производственного кода для точного контракта `<th>Duration</th>` и `<td>…</td>`/`<td>&mdash;</td>`; её использует `mt_call_html_row()`, а отдельный тест проверяет видимые HTML-фрагменты. Фрагмент содержит только фиксированную разметку и вычисленные цифры, исходный текст БД в него не копируется. Все остальные исходные значения по-прежнему HTML-экранируются. `call_idx` не читается рендерером и не публикуется. SQL использует точный `WHERE device=?` и `ORDER BY started_at DESC,id DESC`, tie-break по durable ID.

## Escaping и HTTP errors

Все значения из БД, включая durable ID/номер/времена/direction, в HTML передаются через существующий `mt_html_escape`; Duration fragment не содержит полей из БД и строится только из проверенных цифр/фиксированной разметки. Query links формируются только из имени SIM, предварительно ограниченного `/^[A-Za-z0-9_.-]+$/`, поэтому path сегмент не может содержать HTML/URL delimiters. JSON string fields строятся `ast_json_string_create` и сериализуются Asterisk JSON API (JSON escaping). Любой DB/count/page, JSON object/value construction, setter/append либо serialization error отбрасывает partial envelope и отвечает HTTP 500. Общий JSON error body — `CALL_WEB_JSON_ERROR`; длина в HTTP задаётся `sizeof(CALL_WEB_JSON_ERROR)-1` (37 байт). JSON count failure получает `application/json`, HTML ошибки сохраняют `text/plain`.

## Lock / ownership

SMSDB wrappers держат общий DB mutex весь вызов pager; callback получает временную копию row, валидную только на время вызова. Возврат callback `0` продолжает обход; любой nonzero прекращает обход, но `call_paging_page()` возвращает `0` как успешный early-stop, а не callback failure. Поэтому callback-specific ошибку caller обязан отдельно сохранить в контексте (sticky flag) и проверить после возврата pager; JSON renderer использует для этого `ctx->failed`. Callback не пишет в socket. Для Asterisk JSON API сверены bundled `include/asterisk/json.h` и `main/json.c`: `ast_json_string_create` возвращает NULL при allocation failure; `ast_json_object_set`/`ast_json_array_append` возвращают 0 успех/-1 ошибку, и принимающий object/array забирает переданный value reference даже при ошибке. Поэтому builder заранее отвергает NULL value, проверяет все возвраты и использует дополнительный `ast_json_ref` там, где caller должен сохранить локальное владение для cleanup. Локальные значения/массив/root освобождаются ровно одним `ast_json_unref`; serialization string — `ast_json_free`.

## Изменения и проверки

Изменены `src/call_paging.[ch]` (production SQL pager, строгий UTC parser и duration HTML fragment), `src/smsdb.[ch]` (mutex wrappers), `src/mt_task.c` (routes/render), `src/CMakeLists.txt`, `test/CMakeLists.txt`, `test/call_paging_test.c` и данный документ. `call-paging` CTest использует настоящую in-memory SQLite и production pager: exact SIM/foreign SIM, SQL-like device, все выбранные поля/NULL/truncation, descending ordering/tie, страницы 30/30/остаток, empty/out-of-range, page metadata clamping, malformed schema, step-time SQL error, early stop и production call lifecycle rows. Тесты времени проверяют точный формат ASCII, отказ на пробелах, високосные годы, календарные даты и границы диапазона; тесты HTML-фрагмента сравнивают полную разметку заголовка, положительной/нулевой длительности и маркера недоступного значения. Тест отдельно проверяет, что `sizeof(CALL_WEB_JSON_ERROR)-1 == 37`.

В standalone CTest нет Asterisk JSON runtime/allocator hook: `ast_json_set_alloc_funcs` изменяет allocator глобально для всех JSON-пользователей, поэтому опасно fault-inject-ить его в тестовом процессе драйвера. Остальные части static HTTP renderer, включая полный row с полями, которые экранирует `mt_html_escape`, JSON envelope и socket response, по-прежнему привязаны к Asterisk `ast_str`/socket API и не вызываются в dependency-light pager CTest; их escaping и allocation/setter failure не являются предметом новой Duration seam. Тесты не являются сквозной проверкой HTTP/Asterisk, persistent DB file или устройства. Устройство не использовалось.
