# Счётчики SIM на главной странице — шаг 5 плана 10

## Контракт карточки

Главная `GET /` дополняет карточку каждой SIM тремя отдельными строками: `Всего SMS`, `SMS не доставлено`, `Всего звонков`. Значения фильтруются по точному `device` из карточки. Пустая база даёт три нуля. Существующие `/json`, `/status.json`, SMS-страницы, маршруты и состояние доставки не меняются.

Общее SMS-число не реализовано повторно: `smsdb_sim_metrics()` использует существующий `sms_paging_count()` — тот же подсчёт объединённой истории `mt_queue + mt_out`, что используется SMS-страницами. Недоставленное число отдельное, так как объединённый pager не классифицирует финальные состояния.

## SQL и фактические статусы

`src/sim_metrics.c` выполняет один параметризованный запрос для недоставленных SMS и звонков; `device` связывается ровно один раз. Выражения считают отдельно строки `mt_queue` и `mt_out`, затем складывают их. Незнакомые, но непустые состояния остаются недоставленными, потому что исключаются только точные финальные значения.

Фактическая классификация `mt_queue` (входящие SIM→SIP):

- `new` — недоставлено: новая строка ожидает отправки.
- `queued` — недоставлено: промежуточный SIP-ответ принял сообщение в очередь (например, 202), но доставка ещё не подтверждена; состояние устанавливается обработчиком ответа в `mt_task.c:238`.
- `delivering` — недоставлено: строка выбрана для текущей попытки отправки, но финального положительного ответа пока нет; состояние устанавливается перед отправкой в `mt_task.c:315`.
- `retrying` — недоставлено: доставка будет повторена; в том числе код оставляет конечное исчерпание попыток в этом состоянии с причиной `max attempts reached`, отдельного состояния `failed` в этой таблице нет.
- `delivered` — доставлено, не включается: код устанавливает состояние только при положительном завершённом SIP MESSAGE ответе либо принятом IMDN.

Фактическая классификация `mt_out` (исходящие SIP→SIM):

- `submitted_to_modem` — недоставлено: сообщение передано модему, конечного handset SRR ещё нет.
- `smsc_ok` — недоставлено: SMSC принял сообщение, но доставка на handset не подтверждена.
- `failed` — недоставлено: модем отказал при отправке либо SRR сообщает ошибку (`status & 0x40`). Отдельный failed сохраняется, поскольку это исход конечного отказа.
- `delivered_to_handset` — доставлено, исключается: SRR со статусом `0` подтвердил доставку.
- `srr_status IS NULL` не меняет правила: до отчёта используется сохранённый `state` (`submitted_to_modem` и прочие состояния выше); NULL не трактуется как доставка и не приводит к нулю.

`call_log` считает `COUNT(*) WHERE device=?` для всех строк — входящих, исходящих и пропущенных, завершённых и активных. Активные вызовы намеренно входят в значение.

## DB mutex и ошибки

`smsdb_sim_metrics()` держит общий SMSDB mutex при существующем подсчёте общего SMS и новом запросе metrics. Каждый prepared statement принадлежит своему вызову и освобождается до возврата; общее соединение закрывает только smsdb. Ошибка отсутствующей таблицы/колонки, prepare, bind или выполнения возвращается как ошибка, логируется production wrapper и приводит на `/` к HTTP 500. Нельзя показывать нули вместо ошибки. Два считывания выполняются последовательно под mutex одним wrapper вызовом; это read-only путь, транзакции и жизненный цикл SMS он не меняет.

Рендерер получает реальные счётчики после успешного чтения; он HTML-экранирует имя SIM, а числовые поля форматирует как decimal. При ошибке формата/DB карточка не выдаёт частичный успешный ответ: верхний handler возвращает HTTP 500.

## Тестирование и граница

`sim-metrics` запускает production SQL и HTML helper с реальной in-memory SQLite. Проверяются все MT/MO статусы, включая nullable SRR, отделение двух SIM, активный вызов, нули, отсутствие таблицы и видимые/экранированные HTML значения. Также существующий `sms_paging_count()` продолжает проверяться набором `sms-paging`.

Интеграционная граница: CTest проверяет SQL и renderer, использованные production handler-ом, но не открывает HTTP socket и не запускает Asterisk/PJSIP/модем. Реальные устройства не опрашивались; deployment и runtime smoke вне текущего шага.
